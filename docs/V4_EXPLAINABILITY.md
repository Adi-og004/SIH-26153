## 1. Purpose

V4 forecasts attack probability up to five 10-second windows ahead. This
document establishes what an attribution shown next to one of those
forecasts actually describes, and proves it is computed from the same
checkpoint, tensor, preprocessing, target and horizon as the forecast
itself.

The question the explanation answers:

> *Which parts of the observed 10 × 52 network history contributed to
> this specific future-threat prediction?*

The explainer is a **diagnostic attribution mechanism**. It is a
consumer of the frozen V4 baseline: it trains nothing, tunes nothing,
and writes nothing back to any frozen artifact.

## 3. Input contract

Exactly **10 × 52**: 10 consecutive 10-second windows × 52 features
(26 base + 26 relative-change), in the order frozen in
`docs/v4_feature_schema.json`.

The temporal axis is never flattened. Attribution is returned as
`(N, 10, 52)` and every output row carries `time_step`,
`feature_index` and `feature_name`. `feature_name_integrity.json`
records the index-by-index map and confirms it is identical across all
three sources (schema, `input_feature_names.txt`, live explainer).

No second preprocessing implementation exists. The explainer consumes
the already-constructed inference tensor; the scaler is only ever the
frozen one named above.

## 4. Prediction target

Two target families are supported, and every explanation records which
one it used (`target_type`, `target_horizon`, `target_definition`,
`prediction_probability`).

**TARGET A — `horizon_probability(k)`** *(the default, and the only one
the dashboard displays)*

```
F_k(x) = sigmoid(attack_head(z_k)),   z_k = transition_step^k(encode(x))
```

This is exactly `k_step_rollout(x, K).probs[k]` — the quantity the
frozen reference evaluation thresholds. Frozen validation thresholds:
K=1 → 0.45, K=3 → 0.65, K=5 → 0.72.

**TARGET B — `trajectory_max(K)` = MAX(P(t+1) … P(t+K))**

MAX is not differentiable at ties, and the argmax can move along the
integration path. The explainer therefore attributes `F_{k*}` where
`k*` is the argmax **evaluated at the input**, so the attributed
function value equals the displayed max exactly. Measured on 64
windows: 0 exact ties, but the argmax changes somewhere along the
straight-line path in **43.8 %** of windows. The completeness
reference is consequently `F_{k*}(baseline)`, not `max(baseline)`.
This is recorded per sample in `trajectory_max_explanations.csv` —
documented, not hidden.

No explanation displays one quantity while attributing another.

## 5. Attribution method

**Primary: Integrated Gradients** (`captum.attr.IntegratedGradients`,
`gausslegendre`, `n_steps = 1024`).

IG was retained rather than replaced: it aligns exactly with the V4
computation graph, and the existing implementation was already
gradient-based. `n_steps = 1024` was chosen from the measured
convergence sweep (50 / 128 / 256 / 1024, recorded in
`completeness_checks.csv`) as the first setting whose worst-case
relative completeness error is below 1 % at every horizon — **not** for
appearance.

Correctness conditions, all asserted at construction:

- `model.eval()` — both Dropout layers (0.20 LSTM, 0.10 head) disabled;
  the explainer raises if any Dropout module is still in train mode
- gradients flow through the **input** only; parameters are never stepped
- the attributed output is the actual V4 attack head, reached through
  the model's own `encode` / `transition_step` / `predict_attack`
- attribution dimensionality equals input dimensionality, `(N, 10, 52)`

**Cross-check: Feature Ablation** — model-agnostic and gradient-free
(§ 9).

**Not used:** attention-based explanation (V4 has no attention
mechanism; no attribution is called "attention"), and
`src/shap_explainer.py`, which is retained only for the historical V3
artifacts — it is not provenance-locked, attributes a single transition
step, and draws an unseeded random baseline.

## 6. Baseline / reference definition

**Primary baseline: the zero vector in scaled feature space, shape
(10, 52).**

Principled, not cosmetic: the frozen `StandardScaler` subtracts the
training-partition mean, so the zero vector *is* the average training
window, held constant across all 10 history steps. It is label-free,
independent of the test set, and exactly reproducible.

*Caveat, recorded rather than hidden:* a constant-over-time window is
not itself a realisable capture. This is the standard IG reference-point
compromise.

**Secondary (sensitivity check): the mean of the 6 568 fully-benign
TRAINING sequences** — training labels only, never test labels. Top-10
feature overlap between the two baselines: **8/10 (K=1), 7/10 (K=3),
8/10 (K=5)** — the ranking is substantially but not perfectly
baseline-invariant, as expected for a baseline-relative method.

## 7. Completeness / convergence

For every sample, `sum(attributions)` is compared with
`F(x) − F(baseline)`. Because the attributed output is a probability in
[0, 1], the residual is read on the **probability scale**.

| horizon | mean abs error | p99 abs error | well-posed mean rel error | n well-posed |
|---|---|---|---|---|
| K=1 | 5.048e-04 | 5.200e-03 | 0.212 % | 1 506 |
| K=3 | 7.140e-04 | 5.305e-03 | 0.199 % | 1 813 |
| K=5 | 9.256e-04 | 6.382e-03 | 0.229 % | 1 873 |

Acceptance rule: mean **and** p99 absolute error below 0.01 (one
probability point) at every horizon, plus mean relative error below 1 %
on the well-posed subset. **All pass.**

**Why the unconditioned relative error is large and is reported anyway.**
For many windows the model's prediction nearly equals its prediction at
the baseline, so the denominator `F(x) − F(baseline)` is ≈ 0 and the
ratio degenerates (unconditioned max reaches 1.299e+03 at K=5) while the
probability-scale error stays below 0.02. Both figures are in
`completeness_checks.csv`; the ratio is a degenerate statistic, not a
concealed failure. The relative error is therefore evaluated only where
`|F(x) − F(baseline)| > 0.05`.

## 15. Sanity checks

**A. Model randomisation** — Xavier (≥2-D) / uniform(−0.1, 0.1) (1-D)
re-initialisation of a **deep copy**, three seeds (20260919, 7, 12345);
the production model is never touched and was confirmed unchanged
afterwards.

Mean |Spearman| of **signed** attribution between real and randomised
models: **0.1215** (acceptance: < 0.30). **PASS** — learned structure is
lost.

The discriminating statistic is deliberately the *signed* attribution.
Comparing |attribution| is confounded: IG attribution scales with the
input, so |attr| rank-correlates ≈ 0.6 with |x| for both the real and
the randomised model, leaving a residual top-5 overlap (24–36 %) that is
input-driven rather than evidence of retained model structure. Both are
reported.

**B. Feature perturbation** — mean |Δp| for top-attributed features
(0.1242) exceeds the low-attribution control (0.0109) by 11.4×. **PASS.**

**C. Completeness** — § 7. **PASS.**

None of these were used to tune the model, the thresholds, or the
explanation method.

## 17. Limitations

1. Attribution measures model sensitivity/contribution. It does **not**
   establish causality, attacker intent, attack stage, actual
   compromise, or root cause.
2. Integrated Gradients is a path-integral approximation; the residual
   completeness error is non-zero and is reported per sample.
3. Attributions are baseline-relative. A different reference point
   yields different values (top-10 overlap 7–8/10 between the two
   baselines tested).
4. The trajectory-max target is attributed at a fixed argmax; the argmax
   changes along the integration path in 43.8 % of sampled windows.
5. PCAP explanations inherit the Task 7 finding: flow-record production
   is approximate, so PCAP feature values are not numerically equivalent
   to training features.
6. The V4 checkpoint was trained on single-day `temporal_benchmark_v2`
   arrays and is evaluated on `multiday_benchmark_K5` arrays scaled by a
   different `StandardScaler` (a known frozen-baseline issue).
   Explanations inherit that out-of-distribution-normalisation regime.
7. Re-batching the same frozen model shifts LSTM reduction order by up
   to 1.5e-06. Identity is therefore asserted on the identical tensor in
   the identical batch; batch=1 inference still reproduces the frozen
   K=5 F1 digit-for-digit with **zero** label flips.
8. No K=4 reference threshold exists, so K=4 is not explained against a
   frozen threshold.
9. The stored rule-based MITRE table
   (`models/latent_world_model_v4/mitre_mapping/mitre_summary.csv`) has
   502 rows and is addressed positionally; it predates the move to the
   3 115-window reference benchmark. The dashboard now **refuses** to
   render it rather than misaligning ATT&CK rows against predictions.
   Regenerating it is outstanding work and does not affect any
   attribution result above.

## Appendix — dashboard integration

`src/app.py` previously imported the legacy `shap_explainer`, read the
older `temporal_benchmark_v2` split, used the checkpoint-embedded
threshold 0.05 (a training-time value that the baseline manifest itself
flags as *not* the reference threshold), kept a duplicate copy of the
`LatentWorldModelV4` class and a hand-retyped 52-feature list, and on
the PCAP page displayed `max(P(t+0…t+5))` while its attribution
described a single transition step. The displayed number and the
explained number were therefore different quantities, produced by
different code.

It now:

- obtains the model **only** through `V4Explainer`, which hash-verifies
  the checkpoint, scaler and feature order before returning it — one
  instance serves both the displayed prediction and the explanation
- reads the frozen `multiday_benchmark_K5` reference benchmark
- offers exactly the verified horizons K ∈ {1, 3, 5}, each with its
  frozen validation threshold (0.45 / 0.65 / 0.72)
- loads feature names from the frozen schema and refuses to start if the
  schema and the feature-order file disagree
- renders stored attribution tensors only after their SHA256 matches the
  hash pinned in `results/v4_explainability_summary.json`, and withholds
  them with a visible notice otherwise
- runs a live prediction-identity check on the PCAP path and withholds
  the explanation if it fails
- labels `MODEL ATTRIBUTION` and `ATT&CK INTERPRETATION (rule-based)` as
  separate evidence layers, and describes attribution sign as
  "increased P" / "decreased P" rather than "Attack" / "Benign"

Because the dashboard's prediction now comes from the same verified
rollout as the attribution, the prediction shown and the prediction
explained are the same computation on the same tensor.
